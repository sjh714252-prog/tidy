# M12 작업 지시서 — 폴더 단위 업무 맥락 정리 (사용자 피드백 2026-10-23)

M12 — 폴더 단위 업무 맥락 정리 + 경로 맥락 (버전 0.5.0). 브랜치 `claude/m12-folder-curation`, base main, PR 하나.
먼저 CLAUDE.md, docs/SPEC.md §14.3(M10 큐레이션), §14.6(M11)을 읽고, 아래 설계를 SPEC §14.7로 먼저 적은 뒤 구현한다.

## 무엇이 잘못됐나 (실사용 캡처)
바탕화면의 `중앙선관위 로그\tools\go\...` (Go 툴체인 소스 수백 개) 가 감시 중 자동 맥락 정리로
`D:\정리\기타\개발\소스 코드\a.go`, `기타\개발\테스트 코드\x_test.go`, `기타\개발\샘플 코드\...` 처럼 **파일 단위로 흩어졌다**.
원인 둘: (1) AI에 바로 위 폴더 이름("go")만 보내서 "중앙선관위"를 못 봄. (2) 파일을 하나씩 판단해 한 묶음인 폴더를 쪼갬.
결과: 특정 고객사가 진행한 작업을 찾을 수 없다. 사용자가 원하는 모양: `중앙선관위\20261023_로그분석\개발\go\...` 처럼 **고객사 아래에 프로그램/작업 단위로 뭉쳐** 있어야 한다.

## 1. 경로 맥락을 AI에 준다
- `CurateInput.folder`를 "감시 폴더 기준 상대 경로"로 바꾼다 (`중앙선관위 로그/tools/go`). `CurateFileLine`에 `rel_dir` 추가, 프롬프트 줄은 `폴더: 중앙선관위 로그/tools/go`.
- CURATE_SYSTEM에 추가: "폴더 경로의 **첫 단계**(감시 폴더 바로 아래 폴더 이름)는 그 안 파일 전체의 고객사·이슈를 말해 주는 가장 강한 근거다. 그 이름이 사전의 고객사·별칭과 맞으면 entity로 쓰고, 사전에 없어도 고객사·프로젝트 이름처럼 보이면 그 이름을 entity로 쓴다. 같은 첫 단계 폴더의 파일은 같은 entity·issue를 받는다."
- 사전 "바탕화면에서 뽑기"도 첫 단계 폴더 이름을 고객사 후보로 우선 제시한다.

## 2. 폴더를 하나의 항목으로 (핵심)
- 맥락 정리 대상 폴더를 훑을 때 **감시 폴더 바로 아래 하위 폴더는 통째로 하나의 항목(FolderUnit)** 으로 다룬다. 파일 단위 판단은 감시 폴더 바로 아래 **파일**에만 한다.
  - FolderUnit 요약을 AI에 보낸다: 폴더 이름, 상대 경로, 파일 수, 확장자 분포 상위 5, 대표 파일 이름 10개, 가장 큰/최근 파일, 안쪽 폴더 이름 10개, README·문서 첫 줄 300자. 스키마는 파일과 같되 `kind: "folder"`, `doc_kind`는 "개발", "로그", "자료" 같은 폴더 종류.
  - 제안 목적지: `{entity}/{yyyymmdd}_{issue}/{doc_kind}/{폴더 이름}` (폴더 틀 변수 `{folder}` 추가). 안의 구조는 그대로 옮긴다(폴더 통째 이동 = mover에 `move_dir`: 내부 파일마다 move_log 기록 + 한 배치, 빈 폴더 정리, undo는 역순으로 전부 복원. 복사-검증 경로(NAS)도 지원).
  - 폴더 항목의 날짜는 안쪽 파일 수정일 중 가장 최근 것(사용자 수정 가능).
- 미리보기(정리하기 탭)는 폴더 항목을 한 줄로 보여주고(아이콘 📁, "파일 N개"), 펼치면 안쪽 트리 미리보기. 사용자가 "이 폴더는 파일별로 나눠서"를 고르면 그때만 파일 단위로 다시 분석한다(기본은 폴더 통째).
- 하위 폴더 안을 재귀로 파일별 분석하는 옵션("하위 폴더 포함")은 맥락 정리에서는 **제거**한다(규칙 정리에는 유지).

## 3. 감시 중 자동 맥락 정리의 안전장치
- 감시 중 자동 맥락 정리(설정 ③ "규칙에 안 걸린 새 파일을…")는 **감시 폴더 바로 아래 파일**에만 적용한다. 하위 폴더 안에 생긴 파일은 자동으로 옮기지 않고(규칙 정리는 그대로), 홈의 정리 현황에 "새 폴더 N개 — 지금 정리"로 모아 보여준다.
- 새로 생긴 하위 폴더(복사/압축 해제 등)는 **안정화**(마지막 변경 후 60초, 설정 `curate.folder_settle_secs`)가 끝난 뒤에만 폴더 항목으로 제안한다. 복사 중인 폴더를 옮기지 않는다.
- 자동 이동 확신도 기준(설정 ④ 자동 이동 기준)과 무관하게, 폴더 항목은 **항상 확인 팝업**을 거친다(절대 규칙 6).

## 4. 고객사별로 찾기
- 검색 창에 **고객사 필터**(사전의 고객사 드롭다운): 그 고객사 폴더 아래 파일만. 홈 상단에 "고객사별 보기": 고객사마다 폴더 수·파일 수·마지막 작업일, 클릭하면 탐색기에서 열기.
- 정보 창 옆 "도움말"에 "고객사 자료는 어디 있나요?" 항목 추가(설명서 링크).

## 5. 팝업 용어
- 확인 팝업의 "나중에"를 **"대기열에 두기"** 로 바꾸고 툴팁 "결정을 미룹니다. 확인 대기 탭에 남습니다." (건너뜀/무시 설명은 0.4.1에 이미 있음)

## 6. 테스트
- 코어: `FolderUnit` 요약 생성, `move_dir` 이동/undo(복사-검증 포함, 한글 경로, 중단 복구), 경로 맥락 프롬프트(첫 단계 폴더 이름이 포함되는지), 자동 맥락 정리가 하위 폴더 파일을 건드리지 않는지, 안정화 대기.
- `e2e/m12.mjs`: 바탕화면에 `중앙선관위 로그/tools/go/*.go` 30개 + 바로 아래 파일 몇 개 → 사전에 중앙선관위 → "업무 맥락으로 정리" → 폴더 항목 1개 + 파일 항목 → 적용 → `D:정리/중앙선관위/날짜_로그분석/개발/go/...` 구조 그대로 → 되돌리기 → 원위치. 감시 중 하위 폴더 안 새 파일은 자동 이동 안 됨. 가짜 LLM(fake-llm.mjs)은 폴더 요약 스키마에 답하도록 확장.
- 기존 e2e m3~m11 전부 통과. `cargo test --workspace`, clippy(all-targets, desktop), tsc. 버전 0.5.0, docs/manual.md(5장 재작성: 폴더 단위), SPEC §14.7, CLAUDE.md.
