# M14 작업 지시서 — 중복 파일 처리 + 한글(hwp/hwpx) 본문 검색 (사용자 질문 2026-10-27)

M14 (버전 0.7.0). 브랜치 `claude/m14-duplicates-hwp`, base main, PR 하나.
먼저 CLAUDE.md, docs/SPEC.md §5.4(mover)·§13(.hwp 열린 질문)·§14.8(M13 화면 원칙)을 읽고, 아래 설계를 SPEC §14.9로 먼저 적은 뒤 구현한다. 화면은 M13 원칙(카드·PathText·주 버튼 1개+⋯·좁은 창 카드)을 그대로 따른다.

## 배경
사용자 질문: "동일한 파일이 2개 이상 있으면 어떻게 처리해?" 현재 답: 같은 이름+같은 내용이면 건너뜀(설정 파일로만 바꿀 수 있음), 이름 다르고 내용 같으면 리포트에서 보여주기만 함. 둘 다 화면에서 다룰 수 있어야 한다.

## 1. "똑같은 파일이 이미 있으면" 설정
- `[mover] duplicate_policy`(skip / rename / replace)를 설정 → 고급(또는 감시 폴더 아래 공통 카드)에 노출. 문구: **"옮길 자리에 똑같은 파일이 이미 있으면"** ○ 그대로 두고 건너뜀(기본) ○ 번호를 붙여 둘 다 보관 ○ 기존 것을 휴지통으로 보내고 새것으로. ⓘ 도움말: "이름만 같고 내용이 다르면 언제나 번호를 붙입니다(덮어쓰기 없음)."
- 활동 피드·확인 대기·정리하기 미리보기에서 건너뜀 사유를 사람 말로: "똑같은 파일이 이미 D:\정리\문서\2026-10\에 있어 그대로 둠" + [기존 파일 열기].
- 확인 팝업/확인 대기 행: 제안 위치에 같은 내용 파일이 이미 있으면 미리 알려 준다(제안 계산 때 해시 비교, 500MB 초과는 크기+이름만): "똑같은 파일이 이미 있습니다 → [그대로 두기] [번호 붙여 이동] [기존 것 휴지통 후 이동]" 세 버튼을 그 항목에만 보여준다(⋯ 메뉴 아님, 결정이 필요한 항목이므로). 결정은 `Decision::Move`에 `on_duplicate: Option<DuplicatePolicy>`로 전달.

## 2. 리포트의 중복 그룹 → 정리 동작
- 정리하기 → 리포트 "중복 파일 (N그룹)"에 그룹마다 **남길 파일 선택**(기본: 정리 위치 안에 있는 것 > 가장 오래된 수정일 > 짧은 경로) + 나머지는 **휴지통**. 상단에 "모든 그룹에 기본 선택 적용" 체크 + [미리보기] → 미리보기 표(남김 / 휴지통 N개, 용량 절약) → [적용]. 적용 전 무이동(절대 규칙 6와 같은 승인 흐름).
- 휴지통 보내기는 `mover` 모듈에만(`Mover::trash_duplicates(group, keep)`: `trash` crate, move_log에 `op = trash`로 기록, undo는 OS 휴지통에서 복구 안내만 — Windows/macOS 휴지통 API로 복구가 불가능하므로 `undo`는 "휴지통에서 복원하세요" 메시지 + 휴지통 열기). 절대 규칙 2(삭제 금지 → 휴지통만) 준수.
- 중복 판단은 내용 해시(blake3) 기준, 이름 무관. 감시 폴더 밖(정리 위치)도 그룹에 포함하되 "정리 위치 안 파일은 기본 남김".
- 같은 그룹 안에 하드링크/심볼릭 링크는 제외. 0바이트 파일은 그룹으로 세지 않는다.

## 3. 한글 문서 본문 검색 (SPEC §13 열린 항목 종료)
- `.hwpx`: ZIP + XML(`Contents/section*.xml`의 `<hp:t>` 텍스트). `zip` + `quick-xml`로 구현, 기존 docx 추출기와 같은 구조.
- `.hwp`(5.0 바이너리): `cfb` 크레이트로 복합 문서를 열고 `FileHeader`의 압축/암호 플래그 확인 → `BodyText/Section*` 스트림을 zlib(`flate2`, raw deflate) 해제 → 레코드 헤더(tag id 10비트·level 10비트·size 12비트, size 0xFFF면 다음 4바이트) 순회 → `HWPTAG_PARA_TEXT`(tag 67)의 UTF-16LE 텍스트만 추출(제어 문자 0~31은 인라인/확장 컨트롤 규칙대로 건너뜀: 확장 컨트롤 8자, 인라인 8자, 그 외 1자). 암호 문서·배포용 문서는 "본문 추출 불가(암호)"로 메타만 인덱싱. `PrvText` 스트림(미리보기 텍스트)이 있으면 실패 시 폴백으로 사용.
- `tests/fixtures/`에 작은 `.hwp`·`.hwpx` 샘플(직접 생성 가능한 최소 구조로 만들거나, 공개 라이선스 샘플)과 기대 텍스트 추가. 한글·영문·숫자·표 안 텍스트 포함.
- 개인정보 탐지(M9)도 hwp/hwpx 본문을 읽게 된다(추출기 공유). 설명서 7장·6장 갱신.
- 기존 SPEC §13의 `.hwp` 항목을 "결정(M14)"으로 바꾸고 CLAUDE.md 열린 결정도 갱신.
