# M11 작업 지시서 (사용자 피드백 2026-10-23)

M11 — UI 단순화 + 도움말/정보 + 정리 현황 (버전 0.4.0). 브랜치 `claude/m11-ui-simplify`, base main, PR 하나.
먼저 CLAUDE.md와 docs/SPEC.md §14(특히 14.4, 14.5)를 읽고, 아래 설계를 SPEC §14.6으로 먼저 적은 뒤 구현한다. 사용자(비개발자)가 0.3.0을 쓰며 낸 피드백이다.

## 1. 상태바·감시 정보 재설계 (가독성)
- 지금 상태바는 "감시 중: C:\...Desktop · C:\...Downloads · D:\PC백업_20241031 · D:\백업자료 · 인덱스 50,630개 · AI 사용(...)"이 한 줄에 붙어 나와 구분이 안 된다. 폴더가 4개 이상이면 읽을 수 없다.
- 상태바는 **요약만**: 왼쪽 "감시 중 4곳 · 정리 위치 D:\정리" (정리 위치가 폴더마다 다르면 "정리 위치 2곳"), 가운데 "새 파일 자동 정리 중 / 일시정지 / 연결 끊김 1곳", 오른쪽 "인덱스 50,630 · AI 사용(claude-haiku-5-5)". 각 요소는 아이콘/구분선으로 분리, 긴 경로는 말줄임 + title 툴팁.
- 요약을 클릭하면 **감시 현황 패널**(활동 탭 상단 카드 또는 드롭다운)이 열리고 폴더마다 한 줄: 경로 | 정리 방식(이 폴더 안 / → D:\정리) | 상태(정상·끊김·일시정지) | 제외 N개 | 기존 파일 미정리 N개 [지금 정리]. 표 형식, 경로는 마지막 두 단계만 보이고 전체는 툴팁.

## 2. "정리 시작" 흐름 (사용자가 뭘 눌러야 하는지 모름)
- 활동 탭 맨 위에 **정리 현황 카드**: "새 파일은 자동으로 정리됩니다. 감시를 시작하기 전부터 있던 파일 N개는 아직 정리되지 않았습니다." + 폴더별 N + **[지금 정리]** 버튼. 누르면 리포트 탭으로 가서 그 폴더가 선택되고 "규칙으로 정리 미리보기"(AI가 켜져 있고 맥락 사전이 있으면 "업무 맥락으로 정리"도 나란히)가 바로 실행된다. 미정리 수는 `Curator::files_in`/`existing_files` 기반으로 백그라운드 계산(캐시, 폴더당 상한 20,000개, "20,000+"로 표시), 네트워크 폴더는 건너뜀.
- 리포트 탭의 폴더 드롭다운은 **감시 폴더만** 기본으로 보여주고 "다른 폴더…"는 따로. 선택한 폴더가 어느 감시 폴더의 정리 위치(organize_root)이거나 그 아래면 경고 "이 폴더는 정리 결과가 모이는 곳입니다. 여기서 정리하면 이미 정리된 파일을 다시 옮깁니다." + 버튼은 두 번 확인.
- 모든 미리보기·적용 화면 상단에 한 줄 안내 "적용을 누르기 전에는 아무것도 옮기지 않습니다. 적용 후에도 이동 기록에서 되돌릴 수 있습니다."

## 3. 규칙·정리 위치 불일치 경고
- 감시 폴더가 "지정 위치로 모으기"인데 규칙 목적지가 절대 경로(`C:\`, `D:\`, `~/`)면 규칙 카드와 설정 저장 시 경고 배지: "이 규칙은 기준 폴더(D:\정리)를 무시하고 C:\Users\...\Documents\Tidy\문서 로 보냅니다. 상대 경로(문서/{yyyy}-{mm})로 바꾸면 기준 폴더 아래로 갑니다." + [상대 경로로 바꾸기] 원클릭(절대 경로의 마지막 1~2단계를 상대 경로로 제안).
- 시작 규칙(starter)의 기본 목적지는 모두 상대 경로로 바꾼다(`rules.example.toml`도). 마법사도 동일.

## 4. 도움말 / 정보 메뉴
- 상단바 오른쪽에 **"도움말 ▾"** 메뉴: 사용 설명서(https://github.com/sjh714252-prog/tidy/blob/main/docs/manual.md 를 기본 브라우저로), 문의·버그 신고(https://github.com/sjh714252-prog/tidy/issues/new — 본문에 버전·OS·설정 경로가 미리 채워지도록 쿼리 파라미터 title/body 사용), 업데이트 확인, 정보.
- **정보 창**(작은 모달): Tidy 아이콘, 버전(`app.package_info().version`), 빌드 커밋(짧은 해시, 빌드 시 env로 주입: `TIDY_GIT_SHA`, 없으면 "dev"), 저장소 링크, 라이선스 MIT, 설정 파일 경로·DB 경로(각각 "폴더 열기"), "로그 폴더 열기".
- **업데이트 확인**: `https://api.github.com/repos/sjh714252-prog/tidy/releases/latest`의 `tag_name`(v0.4.1 형식)과 현재 버전을 semver 비교. 새 버전이면 "새 버전 0.4.1 — 받기" 버튼(릴리스 페이지의 Windows setup.exe asset URL을 열기; 없으면 릴리스 페이지). 시작 시 하루 한 번 백그라운드로 확인해 상태바에 작은 "업데이트 있음" 점(설정 ⑥에 끌 수 있는 토글 `general.check_updates`, 기본 켜짐). 네트워크 실패는 조용히 무시, 절대 블로킹 금지. 트레이 메뉴에도 "정보…".
- release.yml: `workflow_dispatch`로 main에서 돌 때도 **공개 릴리스를 만든다** — 태그 `v<apps/desktop/package.json version>`을 Actions 안에서 만들고(GITHUB_TOKEN, 이미 있으면 그 릴리스에 파일 교체) softprops/action-gh-release로 설치 파일 첨부, draft: false. 릴리스 본문은 CHANGELOG 자동(그 버전의 PR 제목 목록). 태그 push 트리거는 그대로.

## 5. 용어·탭 정리
- 탭 이름: 활동 → "홈"(정리 현황 카드 + 활동 피드), 대기열 → "확인 대기", 리포트 → "정리하기", 이동 기록 → "되돌리기", 설정 그대로. 상태바·설명서·e2e 셀렉터(역할+이름 기준이라 이름 바꾸면 e2e도 같이 수정)도 갱신.
- 용어 통일: "재구성"→"정리 제안", "큐레이션"→"업무 맥락 정리", "폴링"→"주기 확인".
