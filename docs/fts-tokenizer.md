# 한국어 FTS5 토크나이저 비교 및 결정 (SPEC §13, M2)

**결정: `trigram`을 주 토크나이저로 채택하고, 1~2글자 질의만 `unicode61` 보조 테이블(prefix 검색)로 처리한다.**

- `files_fts` — `tokenize='trigram'` (주). 3글자 이상 질의는 모두 여기로 간다.
- `files_fts_word` — `tokenize='unicode61 remove_diacritics 2'` (보조). 3글자 미만 질의는 `"과금"*`처럼 prefix 매치로 여기로 간다.
- 두 테이블 모두 `files.content`를 external content로 쓰므로 본문은 한 번만 저장되고, `snippet()`/`highlight()`가 동작한다.
- 질의에 긴 항목과 짧은 항목이 섞이면 trigram 결과를 보조 테이블 결과로 교집합(AND)한다. 구현: `crates/tidy-core/src/search/fts.rs`.

## 왜 하나만 고르지 않았나

한국어 파일명과 본문은 띄어쓰기 없이 붙은 복합어가 많다(`KT과금내역서`, `사업제안서(최종)`, `주차장안내문`). unicode61은 공백·문장부호 단위로만 토큰을 자르므로 복합어의 중간·뒷부분(`내역서`, `제안서`)을 전혀 찾지 못하고, prefix(`*`)를 붙여도 앞부분만 잡힌다. trigram은 부분 문자열 매치라 이 문제가 없지만 **3글자 미만 질의에는 결과가 0건**이다(FTS5 trigram 제약). 한국어 명사는 2음절이 흔하고(`과금`, `예산`, `회의`) 영문 약어(`KT`)도 2글자라 이 구멍을 그대로 둘 수 없어, 짧은 질의만 unicode61 prefix로 보완했다.

비용은 인덱스 크기다(아래 표: 합성 20k 문서 기준 unicode61 93MB + trigram 144MB). 개인 PC 규모(10만 파일 이하, 본문 최대 1,000,000자/파일)에서는 허용 범위로 판단했고, 질의 지연은 두 쪽 모두 수 ms다.

## 성능 (합성 20,000문서, 문서당 ≈300단어 한국어)

| 토크나이저 | DB 크기 | 삽입 시간 | `"과금내역"` | `"보고서"*` / `"보고서"` | `"KT"` |
|---|---|---|---|---|---|
| unicode61 | 92.9 MB | 1.71 s | 0 hits / 0.1 ms | 19999 hits / 3.0 ms | 19998 hits / 1.8 ms |
| trigram | 144.2 MB | 2.67 s | 0 hits / 0.1 ms | 19999 hits / 2.5 ms | 0 hits / 0.0 ms |

(`-` = 결과 없음. `"KT"`의 trigram 0건, `"과금"`의 trigram 0건이 보조 테이블이 필요한 이유다.)

## 알려진 한계

- trigram `highlight()`는 3글자 단위로 표시하므로 스니펫의 강조 구간이 질의보다 조금 넓거나 좁을 수 있다.
- 조사·어미 변형(`보고서를` ↔ `보고서`)은 두 방식 모두 부분 문자열/prefix로 우연히 잡히는 수준이며 형태소 분석은 하지 않는다. 의미검색(M7)에서 보완한다.
- 1~2글자 질의는 "단어 시작" 매치만 된다(`과금` → `과금내역서` ○, `KT과금내역서` ×). 2글자 질의로 복합어 중간을 찾으려면 더 긴 질의를 쓰면 된다.
